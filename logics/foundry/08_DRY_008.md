## Plan d’action
### Passerelle 1 — Socle données & filtrage blessures
1) **Seed** : ajouter 2–3 positions TRANSITION (zones épaules/poignets/dos) pour sécuriser les enchaînements ; ajouter 2 blessures seed (épaule + dos) sur un élève test pour QA générateur.
2) **Helper blessures** : fonction `filterPositionsByInjuries(positions, injuries)` :
   - Exclut les positions ciblant un muscle “forbidden” issu du mapping blessure→muscles.
   - Si le pool est insuffisant, autorise les “atténués” (poids ÷2) et tag `attenuated=true`.
   - Retourne pool filtré + méta (exclusions, atténués).
3) **Intégration générateur** (light) : brancher ce filtrage en amont de la sélection, logguer le nombre exclu/atténué.
4) **QA rapide** : vérifier que le seed passe, qu’un élève blessé voit des propositions filtrées (au moins une exclue/une atténuée visible en log/badge placeholder).

### Passerelle 2 — Répartition 1/2/3/1 + enchaînements + UI
1) **Répartition** : pipeline (après filtrage blessures) :
   - Catégories = niveaux unifiés : Nouveauté, Initié, Passé/Maîtrisé (fusion), Fluide.
   - Slots : 1 Nouveauté, 2 Initié, 3 Passé/Maîtrisé, 1 Fluide.
   - Fallback : si slot vide, prendre la catégorie la plus proche et tagger `fallback=true` (ex: manque de Nouveauté → prendre Initié).
2) **Enchaînements** :
   - Jamais deux TRANSITION de suite.
   - Après TRICK→TRICK, TRICK→SPIN ou SPIN→TRICK, insérer TRANSITION si dispo ; sinon tag “enchâînement non adouci”.
3) **Badges UI** :
   - Dans la prévisualisation du plan : afficher badges “Atténué (blessure)”, “Fallback (catégorie)”, “Enchaînement non adouci” le cas échéant.
4) **QA** :
   - Générateur avec élève blessé (épaule/dos) : vérif exclusions/atténuations + répartition correcte.
   - Niveaux unifiés : progression élève, fiche cours (notes), générateur.
   - Seed toujours OK.
