# 08_DRY_014 — Accès positions via achat de preset ou cours (non-premium)
[Aligné v0.13.0 | Confiance: 70% | Avancement: 0% | Portée: RBAC positions/presets/cours]

Objectif : permettre à un utilisateur non-premium qui a acheté un preset ou un cours d’accéder aux positions incluses (contenu détaillé, médias, tips), sans lever la restriction premium ailleurs.

## Hypothèses / règles d’accès
- Accès position autorisé si : utilisateur premium OU rôle prof/admin OU position libre (free) OU position présente dans un preset acheté (statut PAID) OU position liée à un cours acheté (statut PAID).
- Ne pas ouvrir l’accès à toutes les positions : uniquement celles référencées dans les presets/cours achetés par l’utilisateur.
- Les badges évoluent : afficher un badge “Débloqué par achat” (au lieu de verrou premium) quand l’accès vient d’un achat.

## Étapes proposées
1) Données : récupérer la liste des `positionId` incluses dans les presets achetés (`purchase` kind PRESET + `preset.positions`) et dans les cours achetés (`purchase` kind COURSE + `course.positions`), uniquement pour les achats `PAID` (exclure pending/refunded).
2) Loader positions / détail `/positions/[id]` : ajouter `purchasedViaPresetOrCourse` (boolean + set d’ids) pour l’utilisateur courant.
3) Règle d’affichage : ajuster la condition `canViewPremium` / `showPremiumBadge` pour autoriser la vue si `purchasedViaPresetOrCourse` est vrai même sans premium.
4) API/protection côté serveur (le cas échéant) : s’assurer que les routes qui exposent le détail d’une position (ou médias Cloudinary gated) utilisent la même règle.
5) Tests : cas non-premium sans achat (bloqué), non-premium avec preset contenant la position (autorisé), non-premium avec cours contenant la position (autorisé), premium (autorisé), prof/admin (autorisé).

## Risques / points à confirmer
- Volume de presets/cours achetés : ok pour charger la liste des positions en mémoire ? Sinon filtrage côté requête.
- Vérifier les endroits où `canViewPremium` est dérivé pour ne pas casser d’autres règles (par ex. gating des médias Cloudinary).
- Cas multi-écoles : pour l’instant pas de cross-school ; vérifier si un jour on expose des presets globaux.
- Vérifier dans le code existant comment un “achat de cours” est matérialisé (purchase kind COURSE ou autre) pour brancher la logique correctement.
