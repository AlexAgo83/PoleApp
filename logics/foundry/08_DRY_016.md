# 08_DRY_016 — Synchronisation notes de cours ↔ progression globale
[Aligné v0.13.6 | Confiance: 92% | Avancement: 75% | Portée: sync notes cours → progression + seed]

## Objectif
Unifier la progression élève : les notes saisies dans un cours (statut + commentaire) mettent à jour la progression globale d’une position, tout en conservant la possibilité d’éditer la progression globale manuellement.

## Périmètre (in/out)
- (in) Notes de cours (`course.notes`) : statut + commentaire par position d’un cours.
- (in) Progression globale (`studentPositionProgress`) : statut + commentaire par position/élève.
- (in) Pages concernées : `/teacher/courses/[id]` (saisie prof), `/student/courses/[id]` (vue élève), `/profile` / `/student/progress` (vue globale).
- (in) Seed : cours passés avec positions + notes cohérentes.
- (out) Historique multi-notes ou merge manuel : on applique la dernière note comme source de vérité.

## Règles fonctionnelles
- Dans un cours, le prof saisit uniquement la note locale (statut + commentaire) ; il ne modifie plus la progression globale directement.
- La dernière note (cours) sur une position met à jour `studentPositionProgress` via upsert (statut + commentaire) **sauf si la progression globale est plus récente**.
- Pour dater la “dernière note”, on combine `courseNote.updatedAt` et `course.date` (prendre le plus récent pour comparer).
- L’édition globale reste possible (page dédiée) ; une nouvelle note de cours peut l’écraser uniquement si elle est plus récente.
- La vue élève `/profile` et `/student/progress` reflète la progression globale (icône 📝 si commentaire global). Pas d’indicateur spécifique si la progression globale est plus fraîche (option B : rester silencieux).
- UX prof : toast/indicateur si une note de cours n’écrase pas la globale (globale plus fraîche), avec lien éventuel vers la fiche globale.
- Ajouts schema progression : `lastCourseNoteAt` (DateTime nullable) et `lastCourseNoteSourceId` (String nullable, courseId) pour tracer fraîcheur + provenance.
- RBAC : prof limité à ses cours/élèves pour les notes de cours ; admins école peuvent éditer partout.
- Source de fraîcheur : en cas d’égalité, on privilégie la progression globale (pas d’écrasement).
- Toast proposé : “Note non appliquée : progression globale plus récente. Voir la progression globale.” Lien par défaut vers `/profile` (ou fiche élève si dispo).
- Logging debug optionnel : si `DEBUG_PROGRESS_SYNC=1`, log des décisions “applied/skipped” avec studentId/positionId/courseId + freshness.

## UX cible
- Prof / page cours : formulaire de note inchangé mais sans champ “progression globale”. Feedback implicite ou toast “note appliquée au suivi”.
- Élève / page cours : section “Notes / progression” continue d’afficher les notes du cours.
- Élève / global (`/profile`, `/student/progress`) : statut + icône 📝 proviennent de la progression globale mise à jour.

## Flux technique
1) Création/MAJ d’une note de cours → upsert `studentPositionProgress` (statut + commentaire, `lastCourseNoteAt`, `lastCourseNoteSourceId`) si la note est plus récente que la globale (sinon protéger la globale).
2) Comparaison “dernière note” : `noteFreshness = max(courseNote.updatedAt, course.date)` vs `globalFreshness = max(studentPositionProgress.updatedAt, lastCourseNoteAt)`. Si égalité, ne pas écraser la globale.
3) Supprimer toute écriture directe de progression globale dans le formulaire cours.
4) Pas de rétro-propagation auto des anciennes notes (reset/seed plutôt qu’une migration).
5) Sécurité action : même schoolId + prof = teacherId du cours (ou admin). Élève doit être inscrit pour la note.

- ## Tests & seed
- Unit/integration : création/MAJ de note de cours → progression globale mise à jour ; cas où la globale est plus récente (ne pas l’écraser) ; égalité = ne pas écraser.
- Intégration : vérifier toast “note non appliquée” côté prof + protection globale.
- E2E/QA : saisie note cours, vérif affichage dans `/student/courses/[id]` et reflet dans `/profile` (icône 📝).
- Seed : fait (≥5 cours passés, ≥5 positions, notes variées/commentées, cas de blocage global plus frais). Reset/seed validé.
