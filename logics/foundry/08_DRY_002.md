# 08 — DRY plan (Facturation)
[Confiance: 80%, Avancement: 0%, Temps restant estimé: 10H]
Contexte : 
- Objectif : livrer un module de facturation basé sur `Invoice` couvrant Admin (S006) et Teacher (S005) + backfill legacy.
- Contrainte : phase produit → fiabilité, RBAC strict, pagination 10, filtres, pas d’erreur runtime, lint ok.
- Périmètre technique retenu : table `Invoice` liée à `Course` (courseId, amountCents, currency, status enum Générée/Envoyée/Payée/En retard/Annulée, issuedAt, paidAt, notes).

## Plan
1) Modèle & backfill
- [ ] Migration Prisma : table `Invoice` (PK id UUID, courseId FK unique, amountCents int, currency text default EUR, status enum, issuedAt, paidAt, note nullable, timestamps).
- [ ] Seed/backfill : pour chaque course existante → Invoice statut “GENERATED”, montant calculé (règle par défaut : présences CONFIRMED × 50€ ; fallback maxSeats × 30€) ; issuedAt = now ; permettre override montant/note côté admin.
- [ ] Prisma client regen + types `InvoiceStatus`.

2) API/serveur
- [ ] Repositories ou helpers pour lire/list invoices avec filtres (date range course.date, teacherId, studioId, status).
- [ ] Actions server (admin) : update statut (GENERATED → SENT → PAID / LATE / CANCELLED) avec flow guidé (bouton marquer envoyé/payé), override montant/note, set issuedAt/paidAt.
- [ ] Validation zod côté actions, RBAC (SCHOOL_ADMIN écriture, TEACHER lecture sur ses cours si validé).

3) UI Admin – Facturation
- [ ] Nouvelle page `/app/admin/billing` : liste paginée (10), filtres (date min/max, prof, studio, statut), colonnes cours/date/studio/prof/élèves/count, montant, statut (badges), actions statut guidées + edit montant/note inline.
- [ ] Export CSV bouton.
- [ ] Lien retour dashboard admin + liens vers cours/teacher/studio.

4) UI Teacher – Facturation (lecture)
- [ ] Onglet/section `/app/teacher/billing` ou bloc dans cours : liste readonly des invoices de ses cours, filtres date/studio/statut, pagination 10.
- [ ] RBAC : lecture seule confirmée pour TEACHER, pas d’actions.

5) Observabilité & qualité
- [ ] Logs structurés sur updates d’Invoice (avant/après status).
- [ ] Tests unitaires simples sur calcul montant par défaut + mapping statut.
- [ ] Lint/format + mise à jour README/CHANGELOG/backlogs S002/S005/S006 + homepage module facturation.

## Ouverts / arbitrages
- Règle de calcul par défaut : fixée (présences confirmées × 50€, fallback maxSeats × 30€), override admin possible.
- Accès TEACHER : lecture autorisée sur ses cours (ok).
- Export CSV : à inclure en V1.
- Actions guidées : boutons “Marquer envoyé/Payé/Annulé/Retard” en plus du select.
- Champs supplémentaires : taxe/TVA (%) et totalTTC à prévoir ? (non lancé)
