# 08 — DRY plan (Facturation)
[Aligné v0.12.11 | Confiance: 92% | Avancement: 100% | Statut: livré]
Contexte : 
- Objectif : livrer un module de facturation basé sur `Invoice` couvrant Admin (S006) et Teacher (S005) + backfill legacy.
- Contrainte : phase produit → fiabilité, RBAC strict, pagination 10, filtres, pas d’erreur runtime, lint ok.
- Périmètre technique retenu : table `Invoice` liée à `Course` (courseId, amountCents, currency, status enum Générée/Envoyée/Payée/En retard/Annulée, issuedAt, paidAt, notes).

## Plan
1) Modèle & backfill
- [x] Migration Prisma : table `Invoice` (PK id UUID, courseId FK unique, amountCents int, currency text default EUR, status enum, issuedAt, paidAt, note nullable, timestamps).
- [x] Seed/backfill : pour chaque course existante → Invoice statut “GENERATED”, montant calculé (règle par défaut : présences CONFIRMED × 50€ ; fallback maxSeats × 30€) ; issuedAt = now ; override montant/note côté admin.
- [x] Prisma client regen + types `InvoiceStatus`.

2) API/serveur
- [x] Liste invoices avec filtres (date range course.date, teacherId, studioId, status).
- [x] Actions server (admin) : update statut (GENERATED → SENT → PAID / LATE / CANCELLED) avec flow guidé (boutons rapides), override montant/note, set issuedAt/paidAt.
- [x] Validation zod côté actions, RBAC (SCHOOL_ADMIN écriture, TEACHER lecture sur ses cours).

3) UI Admin – Facturation
- [x] Page `/app/admin/billing` : liste paginée (10), filtres (date min/max, prof, studio, statut), colonnes cours/date/studio/prof/élèves/count, montant, statut (badges), actions statut guidées + edit montant/note inline.
- [x] Export CSV (bouton + route API).
- [x] Lien retour dashboard admin + liens vers cours/teacher/studio.

4) UI Teacher – Facturation (lecture)
- [x] Onglet `/app/teacher/billing` : liste readonly des invoices de ses cours, filtres date/studio/statut, pagination 10.
- [x] RBAC : lecture seule confirmée pour TEACHER.

5) Observabilité & qualité
- [x] Logs structurés sur updates d’Invoice (avant/après status).
- [x] Tests unitaires simples sur calcul montant par défaut.
- [x] README/CHANGELOG/backlogs alignés + lint ok.

## Ouverts / arbitrages
- Règle de calcul par défaut : fixée (présences confirmées × 50€, fallback maxSeats × 30€), override admin possible.
- Accès TEACHER : lecture autorisée sur ses cours (ok).
- Export CSV : à inclure en V1.
- Actions guidées : boutons “Marquer envoyé/Payé/Annulé/Retard” en plus du select.
- TVA/TTC : à implémenter (champ TVA %, total TTC, valeur par défaut 20%).
