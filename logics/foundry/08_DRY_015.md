# 08_DRY_015 — Audit médias Cloudinary vs base (Super Admin)
[Aligné v0.12.11 | Confiance: 85% | Avancement: 0% | Portée: audit Cloudinary/DB]

## Objectif
Ajouter dans l’espace super-admin une page d’audit des médias qui croise les assets présents dans Cloudinary et les références stockées en base afin d’identifier : (1) les assets Cloudinary orphelins (présents Cloudinary, absents DB) ; (2) les références cassées en DB (référencées en DB mais absentes Cloudinary).

## Périmètre (in/out)
- (in) Cloudinary `resource_type` image et video, `type` upload + authenticated, filtres par dossier/prefix et éventuellement tag ; pagination via `next_cursor`.
- (in) Références DB : `User.avatarPublicId`, `School.photoPublicId`, `Studio.photoPublicId`, `Course.photoPublicId`, `PositionMedia.publicId` (video/image), `Preset.imagePublicId`, `Preset.videoPublicId` (+ `PositionMedia.url` si c’est une URL Cloudinary sans publicId stocké).
- (out) Suppression automatique des assets ou corrections DB ; actions destructives seront gérées plus tard (phase lecture/CSV uniquement).
- (out) Audit d’autres providers (Mapbox, partenaires) ou fichiers statiques hors Cloudinary.

## Sources et mapping DB
- `User.avatarPublicId` → image, type upload (sauf avatars seed), dossier attendu `poleapp/users/` si configuré.
- `School.photoPublicId`, `Studio.photoPublicId`, `Course.photoPublicId` → image, type upload, dossiers `poleapp/schools|studios|courses`.
- `PositionMedia`: `kind=PHOTO|VIDEO` → resource_type image|video, type upload ou authenticated (vidéos auth pour positions). `publicId` prioritaire ; si absent, essayer de parser `url` Cloudinary (basename).
- `Preset.imagePublicId` (image/upload) et `Preset.videoPublicId` (video/upload ou authenticated).
- Rappeler que certains seeds/avatars peuvent être stockés sans dossier (basename seul) : prévoir le matching basename.

## Règles de matching
- Normaliser les public_id DB : trim, retirer éventuelle racine dossier connue (`poleapp/*`), retirer l’extension `.jpg/.mp4` si présente, prendre la partie après `image/upload/` ou `video/upload/` pour les champs `url` (PositionMedia). Réutiliser si possible `normalizeFolderedPublicId` ou un helper dédié pour éviter les doublons `folder/folder/id`.
- Normaliser les assets Cloudinary : collecter `public_id`, `resource_type`, `type`, `folder`, `bytes`, `format`, `created_at`, `tags`. Stocker le `public_id` complet (avec dossier) et calculer aussi une version “basename” (sans dossier) pour matcher les cas DB sans dossier.
- Définir deux ensembles :  
  - A = public_id Cloudinary (complet + basename).  
  - B = public_id DB (normalisés).  
  Orphelins = A \ B ; Références cassées = B \ A. Garder le détail (source table/rowId pour B, dossier/format/taille pour A).
- Seed/placeholders : identifier explicitement les assets seed (ex: `SEED_MEDIA_IDS`, `CLOUDINARY_AVATAR_DEFAULT_IDS`) et les flagger dans le résultat ; par défaut exclus du diff/exports mais visibles via badge si réintégrés plus tard.
- Ignore list : exclure les placeholders/seed connus (par défaut) et prévoir un flag côté service si besoin de les réintégrer ; option pour masquer les assets signés “auth” de test.

## UX cible (page `/super-admin/media-audit`)
- Accès super-admin uniquement, panneau dédié dans la home super-admin (carte “Audit médias Cloudinary”).
- Contrôles : sélection du `resource_type` (image/video), du `type` (upload/authenticated), exclusion par défaut du dossier `samples/` de Cloudinary, limite de résultats (par défaut 200) et bouton “Scanner”. (Prefix retiré de l’UI ; scan global ou cible via code si besoin.)
- Résultat : un écran unique avec filtre “Orphelins Cloudinary / Références cassées DB / Tous”. Chaque ligne affiche `public_id`, dossier/prefix, type (image/video, upload/auth), taille/format/date côté Cloudinary ou table/champ/id côté DB, **badge seed/placeholder** quand applicable. Bouton “Exporter CSV” (un fichier avec une colonne `category=orphan|missing` ou deux exports séparés si besoin). Paginé côté UI (client) à partir des résultats calculés serveur.
- Statistiques en tête de page : nb scanné Cloudinary, nb références DB, nb orphelins, nb cassés, temps de scan, horodatage du dernier run.
- États de chargement/erreur : spinner, message d’erreur Cloudinary (quota, timeout), option “Relancer”.

## Flux technique
1) **Collecte DB** : service `collectDbMediaRefs` qui retourne `Set` + détails (table, id, champ, resourceType supposé, isSeed). Inclure parsing des `PositionMedia.url` Cloudinary (regex `res.cloudinary.com/.../(image|video)/upload/(.*?)(\\.\\w+)?$`). Garder trace du `kind` pour les vidéos authenticated.
2) **Collecte Cloudinary** : service `collectCloudinaryAssets({ resourceType, type, prefix, maxResults })` qui appelle l’API Admin `/resources/{resourceType}` avec `type` et `prefix`, boucle `next_cursor` jusqu’à la limite demandée (cap 500/500*pages). Timeout/garde-fou et logs. Marquer isSeed si `public_id` match les seeds/avatars.
3) **Diff** : fonction pure qui calcule `orphans` et `missing`, conserve les métadonnées utiles pour l’affichage/CSV (public_id, resource_type, type, folder, bytes, format, created_at, isSeed / table, id, champ).
4) **API / server action** : endpoint protégé (super-admin) qui orchestre 1–3 et retourne un payload paginé + stats. Pas de clé Cloudinary côté client. Ajouter logs/audit (`auditLog`) avec stats (nb assets scannés, orphelins, cassés) et paramètres utilisés (type, resource_type, maxResults, prefix si appliqué).
5) **Cache/limites** : limiter la fréquence (ex : 1 scan par minute par user) via clé KV/Memory ; option “forcer un rescan” qui bypass le cache ; TTL court (ex: 5 min) pour réutiliser les résultats récents.
6) **Export CSV** : générer serveur (2 fichiers distincts) et fournir un lien download (pas de traitement client lourd). Colonnes Cloudinary : `public_id,basename,folder,resource_type,type,bytes,format,created_at,is_seed`. Colonnes DB cassées : `public_id,table,field,record_id,resource_type,expected_type,is_seed`.

## Risques / points ouverts
- **Quota/latence API Cloudinary** : `max_results` limité à 500 par page, risques de timeout si scan complet. Mitiger via prefix/dossier et caps UI.  
- **Types mixtes** : positions vidéo peuvent être en `type=authenticated`, avatars/photos en `upload`. S’assurer que le scan couvre les deux (ou un toggle clair).  
- **Normalisation** : public_id en base sans dossier ou avec extension ; bien aligner pour éviter les faux positifs.  
- **Sécurité** : pas d’expo des credentials côté client ; endpoint protégé RBAC + rate limit.  
- **Faux positifs seeds** : seed ids ou avatars par défaut éventuellement non utilisés en DB ; exclus par défaut, prévoir un flag service si besoin de les réintégrer.
