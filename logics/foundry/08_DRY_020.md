# 08_DRY_020 — Optimisations perfs/ops (agendas, Prisma, médias, DB)
[Aligné v0.15.0 | Compréhension: 100% | Confiance: 100% | Avancement: 60% | Portée: perfs (requêtes Prisma, médias), cache agendas, bonnes pratiques DB/dumps]

## Objectif
Réduire la charge DB et le poids des assets, améliorer la réactivité des agendas, et sécuriser les opérations DB (dumps/env) sans refonte fonctionnelle.

## Périmètre (in/out)
- (in) Optimisations techniques : indexes Prisma, sélections `select`, cache agendas, poids médias (icônes/boutons), scripts ops (dump/chiffrage).
- (out) Nouvelle fonctionnalité métier, refonte UI complète, changement de provider DB.

## Règles fonctionnelles / attentes
- Fonctionnel inchangé pour l’utilisateur final : mêmes écrans/CTA, données identiques.
- Pas d’augmentation de la fenêtre agenda (maintenir limites existantes).
- Ops : manipuler les dumps prod de façon sécurisée (fichiers hors repo, pas de reset prod).

## UX cible
- Agendas / listes : chargement plus rapide (latence perçue réduite), aucun changement visuel.
- Boutons contact : icônes conservées mais allégées (WebP si possible) sans perte de qualité.

- Données / technique
- Prisma / DB :
  - Indexes existants : `Course` a déjà `@@index([schoolId, date, teacherId, studioId])` et `@@index([schoolId, date])`; `User` a `@@index([email])`, `@@index([role, isPremium])`; `Notification` a `@@index([userId, readAt, createdAt])` et `@@index([userId, createdAt])`. Vérifier s’ils couvrent les requêtes cible via `EXPLAIN` et compléter si besoin (ex. composite `userId, kind, courseId, createdAt` déjà présent).
  - Requêtes à cibler : agendas (`/api/student|teacher|admin/week-courses`, `/api/teacher/month-courses`, `/api/teachers/[id]/week-agenda`), listes prof/élève (`/app/teacher/students`, `/app/admin/users`), listes cours (`/app/teacher/courses`, `/app/admin/courses`).
  - Restreindre les `select` aux champs utilisés sur les listes/agendas (teachers/students/courses) pour limiter le payload :
    - Agenda : `id`, `title`, `date/start/end`, `duration`, `teacherId/name`, `studio{id,name,address,city?}`, `status/canceled`, `isVirtual`, discipline/badges si affichés ; pas d’includes positions/attendances en liste.
    - Liste prof/élève : `id`, `firstName/lastName/name`, `email`, `role`, `schoolId`, `isPremium`, `avatarPublicId` (pas d’includes favoris/progress).
    - Liste cours : id/date/titre/studio/teacher/disciplines/status/canceled/isVirtual uniquement ; positions/attendances chargées seulement sur la fiche détail.
- Agendas :
  - Cache : revalidate serveur 60s sur les routes agendas, sans SWR client. Invalidation explicite sur annulation/inscription/édition de cours via `revalidatePath`.
  - Garder le filtrage `schoolId/teacherId` forcé côté serveur.
- Médias :
  - Rester en PNG optimisés pour les icônes contact (pas de WebP) ; vérifier l’usage `next/image` + `loading=\"lazy\"` sur les listes à forte volumétrie (cours/teachers/students).
- Ops DB :
  - Script/dossier dédié pour dumps (`/dump`) hors repo git, nommage timestamp, chiffrement par défaut (zip+mdp ou gpg). Jamais de dump/reset avec l’URL prod en local.
  - `.env.example` : séparer clairement URLs prod/test et rappeler de n’utiliser que les URLs de test pour seed/reset.

## Tests & QA à prévoir
- Agendas : navigation semaine (teacher/student/admin) reste correcte, filtres/teacherId non contournables, état vide inchangé.
- Listes : aucune régression visuelle ; données complètes malgré les `select` restreints.
- Perfs : vérifier la présence des indexes via Prisma studio/DB (explain si possible) et mesurer temps moyen de requête (log Prisma).
- Médias : boutons contact s’affichent avec les nouvelles icônes optimisées ; pas de régression `next/image`.
- Ops : dump/restore test avec URL de test, aucun fichier dump ajouté au repo.

## Plan & tâches (proposé)
- [x] Revue des indexes manquants : `Course` couvre déjà `schoolId/date/teacherId/studioId`, `User` couvre `email` + `role/isPremium`, `Notification` couvre `userId + createdAt/readAt/kind`. Pas de migration ajoutée ; prévoir EXPLAIN ponctuel en prod/staging si besoin.
- [x] Réduire les `select` Prisma sur listes/agendas (teachers/students/courses) aux champs affichés. _Fait : listes élèves, agenda cours prof, liste cours prof, liste profs admin, liste partenaires admin ; autres listes déjà en select minimal._
- [x] Agendas : cache court serveur (revalidate 60s) + revalidatePath après mutation.
- [ ] Médias : optimiser les icônes contact (PNG optimisé) et valider l’usage `next/image` sur listes lourdes.
- [x] Ops : script dump/restore sécurisé (test DB) avec chiffrement optionnel, doc `.env.example` (URLs prod/test séparées), exclusion git des dumps.

## Risques / points ouverts
- Indexes : risque de migration plus lente sur DB large ; valider avec DBA si volumétrie importante.
- Cache agendas : cohérence des données en cas de modifications fréquentes (annulations/inscriptions) ; choisir une durée faible.
- Icônes WebP : compatibilité charte/affichage ; fallback PNG si nécessaire.
- Ops : manipulation des dumps prod à encadrer (chiffrement, stockage sûr).
