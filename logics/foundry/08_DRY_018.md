# 08_DRY_018 — Agenda fiche prof (élève) + localisation
[Aligné v0.14.x | Compréhension: 100% | Confiance: 88% | Avancement: 0% | Portée: fiche prof → agenda semaine filtré + infos lieux]

## Objectif
Répondre au QA S017 (2026-01-05, v0.14.x) : depuis la fiche d’un professeur, un élève veut voir son agenda (cours à venir) et savoir où il est localisé (école/studios ou en ligne).

## Périmètre (in/out)
- (in) Page fiche prof `/teachers/[id]` visitée par un élève connecté (ou prof/admin), vue publique interne.
- (in) Agenda des cours du prof (semaine en cours + navigation), CTA vers le détail du cours/inscription.
- (in) Localisation : école du prof + studios/adresses des cours futurs (ou mention “En ligne” si virtuel).
- (out) Prise de rendez-vous hors cours, contact direct, ICS dédié ou export personnel.
- (out) Modification des données prof/école/studio (édition reste côté staff).

## Règles fonctionnelles
- Accès & scope : fiche prof requiert session ; les cours affichés respectent la schoolId de l’utilisateur (pas de fuite inter-écoles). Si prof sans school ou hors périmètre élève, afficher fiche mais agenda vide + message.
- Agenda prof :
  - Vue semaine en cours par défaut ; navigation semaine -1/+1 (limiter à ±8 semaines pour éviter la dérive).
  - Filtre forcé `teacherId` = prof consulté ; autres filtres désactivés ou masqués.
  - Cartes cours : titre, date/heure, durée, discipline, studio (ou “En ligne”), statut perso (inscrit/liste d’attente) si disponible, CTA “Voir le cours” menant au détail.
  - Si aucun cours futur : état vide explicite + lien vers liste cours avec filtre prof.
- Localisation :
  - Bloc dédié listant l’école (nom déjà affiché) + studios où le prof a des cours à venir (nom + adresse si renseignée).
  - Mention “En ligne” si au moins un cours `isVirtual`; sinon rien.
  - Si aucune info lieu : “Localisation non renseignée”.
- Tracking/UX : conserver le bouton “Partager” existant ; conserver retour `from` sur les liens cours pour revenir à la fiche prof.

## UX cible
- Section “Agenda du professeur” ajoutée sous la fiche : composant agenda semaine compact, nav ← actuelle →, badges “Inscrit”/“Liste d’attente” si applicables, puce “En ligne” ou nom du studio visible sur chaque carte. Layout et habillage calqués sur “Planning - Agenda de l’école” de `/teacher/school` (panel/section identiques pour cohérence).
- Section “Localisation” (panel ou sous-bloc dans l’entête) listant école + studios + adresses ; icône lieu ; fallback texte si vide.
- Lien “Voir tous ses cours” vers `/student/courses?teacher={id}` (callback vers fiche prof).

## Données / technique
- Réutiliser le fetch existant `/api/student/week-courses` avec filtre `teacher`. Initialiser serveur-side la semaine en cours (helper partagé avec agendas student/teacher) pour fournir `initialWeek/prev/next/days`. Récupérer le même composant/structure visuelle que “Planning - Agenda de l’école” (/teacher/school) en variant uniquement les données/CTA. Forcer côté serveur le `teacherId` consulté (param non overridable par le client) + filtrage schoolId.
- Ajout d’un loader Prisma pour récupérer les studios distincts des prochains cours du prof (>= aujourd’hui), incluant `studio.name/address` et flag `isVirtual`. Pas de nouvelle table.
- Respecter la schoolId : requêtes cours filtrées sur `course.schoolId = session.user.schoolId` sauf super-admin.
- Links cours : conserver `from=/teachers/{id}` pour retour.
- Perf : cache no-store déjà en place sur l’agenda ; limiter la fenêtre temporelle à 16 semaines max.

## Tests & QA à prévoir
- Élève connecté voit l’agenda du prof courant semaine ; navigation fonctionne et reste filtrée par prof.
- Cours virtuel affiche “En ligne”; cours avec studio affiche le nom (et adresse si présente).
- Prof sans cours futurs → message vide + lien “Voir tous ses cours”.
- Élève d’une autre école ne voit pas les cours d’un prof hors de son école (agenda vide ou 404 contrôlé).
- Lien retour `from` ramène bien sur la fiche prof.
- UI/contrôles alignés avec “Planning - Agenda de l’école” (/teacher/school) : mêmes filtres/legendes/CTA/boutons, seule la source de données change.
- Filtre `teacherId` non contournable : l’agenda affiché est toujours celui du prof courant, même si le client modifie l’URL.
