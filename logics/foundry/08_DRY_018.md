# 08_DRY_018 — Agenda fiche prof (élève) + localisation
[Aligné v0.14.x | Compréhension: 100% | Confiance: 100% | Avancement: 100% | Portée: fiche prof → agenda semaine filtré + infos lieux]

## Objectif
Répondre au QA S017 (2026-01-05, v0.14.x) : sur la fiche d’un professeur, permettre de voir son agenda (cours à venir) et sa localisation (ville via studios fréquentés, y compris cours non validés), visible rapidement et réutilisant le planning teacher/school.

## Périmètre (in/out)
- (in) Page fiche prof `/teachers/[id]` pour utilisateurs connectés (élève/prof/admin/super-admin).
- (in) Agenda des cours du prof (semaine en cours + navigation), CTA vers le détail du cours/inscription.
- (in) Localisation : école du prof + studios/adresses/villes des cours futurs (y compris cours non validés avec studio obligatoire).
- (out) Prise de rendez-vous hors cours, contact direct, ICS dédié ou export personnel.
- (out) Modification des données prof/école/studio (édition reste côté staff).

## Règles fonctionnelles
- Accès & scope : fiche prof requiert session ; les cours affichés respectent la schoolId de l’utilisateur (pas de fuite inter-écoles). Si prof hors schoolId de l’utilisateur, refuser l’accès (404/accès interdit). Prof sans school ou multi-écoles : on filtre sur la schoolId de l’utilisateur (agenda potentiellement vide). Agenda consultable par tous les rôles connectés (élève pour réserver, autres pour voir l’activité).
- Agenda prof :
  - Vue semaine en cours par défaut ; navigation semaine -1/+1 sans blocage de fenêtre.
  - Filtre forcé `teacherId` = prof consulté ; autres filtres désactivés ou masqués.
  - Cartes cours : titre, date/heure, durée, discipline, studio (pas de mention “En ligne”), statut perso (inscrit/liste d’attente) uniquement pour les élèves, badge “Annulé” si le cours l’est, style existant bordure jaune + emoji note/calendrier pour les cours non validés (flag interne `isVirtual`) ; CTA “Voir le cours” menant au détail pour tous les rôles.
  - Si aucun cours futur : état vide explicite + lien vers liste cours avec filtre prof.
- Localisation :
  - Bloc dédié listant l’école (nom déjà affiché) + studios où le prof a des cours à venir (nom + adresse/ville si renseignée).
  - Cours non validés (flag interne `isVirtual`) restent associés à leur studio ; pas de mention “En ligne”. Les studios peuvent apparaître en doublon (une occurrence par cours).
  - Si aucune info lieu : “Localisation non renseignée”.
- Tracking/UX : conserver le bouton “Partager” existant ; conserver retour `from` sur les liens cours pour revenir à la fiche prof.

## UX cible
- Section “Agenda du professeur” ajoutée sous la fiche, avant les sections “Édition” : composant agenda semaine compact, nav ← actuelle →, badges “Inscrit”/“Liste d’attente” si applicables (élèves uniquement), badge “Annulé” si besoin, puce studio/ville visible sur chaque carte. Les cours non validés (flag interne `isVirtual`) reprennent le style existant (bordure jaune + emoji note/calendrier). Layout et habillage calqués sur “Planning - Agenda de l’école” de `/teacher/school` (panel/section identiques pour cohérence).
- Section “Localisation” (panel ou sous-bloc dans l’entête) listant école + studios + adresses/ville (occurrence par cours) ; icône lieu ; fallback texte si vide.
- Lien “Voir tous ses cours” vers `/student/courses?teacher={id}` (callback vers fiche prof).

## Données / technique
- Réutiliser le fetch existant `/api/student/week-courses` avec filtre `teacher`. Initialiser serveur-side la semaine en cours (helper partagé avec agendas student/teacher) pour fournir `initialWeek/prev/next/days`. Récupérer le même composant/structure visuelle que “Planning - Agenda de l’école” (/teacher/school) en variant uniquement les données/CTA. Forcer côté serveur le `teacherId` consulté (param non overridable par le client) + filtrage schoolId.
- Ajout d’un loader Prisma pour récupérer les studios des prochains cours du prof (>= aujourd’hui), incluant `studio.name/address`/ville et flag `isVirtual` (cours non validé mais avec studio). Pas de nouvelle table.
- Respecter la schoolId : requêtes cours filtrées sur `course.schoolId = session.user.schoolId` sauf super-admin.
- Links cours : conserver `from=/teachers/{id}` pour retour.
- Perf : cache no-store déjà en place sur l’agenda ; navigation libre (surveiller si besoin une limite ultérieure).

## Tests & QA à prévoir
- Élève connecté voit l’agenda du prof courant semaine ; navigation fonctionne et reste filtrée par prof.
- Cours non validé (flag interne `isVirtual`) reprend le style bordure jaune + emoji note/calendrier, affiche son studio (pas de mention “En ligne”) ; cours annulé affiche un badge “Annulé”.
- Prof sans cours futurs → message vide + lien “Voir tous ses cours”.
- Élève d’une autre école ne voit pas les cours d’un prof hors de son école (404/accès refusé).
- Lien retour `from` ramène bien sur la fiche prof.
- UI/contrôles alignés avec “Planning - Agenda de l’école” (/teacher/school) : mêmes filtres/legendes/CTA/boutons, seule la source de données change ; badges “Inscrit”/“Liste d’attente” seulement pour les élèves.
- Localisation liste bien les studios de chaque cours à venir (doublons autorisés), adresse/ville affichée si présente.
- Filtre `teacherId` non contournable : l’agenda affiché est toujours celui du prof courant, même si le client modifie l’URL.
- Lancer tests unit/integration pertinents + test de build après implémentation.

- Cohérence visuelle : respecter le style existant des cours non validés (bordure jaune + emoji) et l’ajout du badge “Annulé”.
