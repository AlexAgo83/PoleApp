# 08_DRY_010 — Vidéos Cloudinary pour positions (upload signé + lecteur)
[Aligné v0.12.11 | Confiance: 95% | Avancement: 100% | Portée: S011 P? | Obsolete]

## Objectif
Permettre l’upload de vidéos de positions vers Cloudinary (upload signé côté serveur), stocker l’URL dans la position, et afficher un lecteur vidéo intégré (poster généré). Options de remplacement/suppression sécurisées.

## Portée (in) / (out)
- (in) Upload signé Cloudinary pour positions, stockage `videoUrl`/`videoPublicId`, preview/lecture native `<video>`, remplacement/suppression du média.
- (out) Transcodage avancé, quotas/billing Cloudinary, upload multi-fichiers (audio/steps), gestion hors positions (cours/presets) sauf si demandé ensuite.

## Hypothèses / Pré-requis
- Env à ajouter : `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, `CLOUDINARY_FOLDER` (ex: poleapp/positions), `MAX_VIDEO_MB` optionnel.
- Provider Cloudinary autorisé pour les images/vidéos (host déjà whitelisted si besoin).
- Champ `videoUrl` déjà présent sur Position; ajouter `videoPublicId` si on veut supprimer/remplacer proprement.

## Réalisé
1) **Modèle / Prisma** : champ `publicId` sur `PositionMedia` (vidéos). Seed avec vidéos Cloudinary authenticated (round-robin).
2) **Signature upload (server)** : `/api/uploads/signature` signe `type=authenticated` + `access_mode=authenticated`, contrôle auth; delete `/api/uploads` gère type/delivery.
3) **UI upload (formulaire position)** : composant `CloudinaryUpload` (video, max 100MB) dans création/édition prof, hidden `videoUrl` + `videoPublicId`, suppression Cloudinary si remplacement.
4) **Lecture / preview** : fiche position utilise URL signée (helper `generateSignedUrl`) pour vidéos authenticated; liste affiche badge vidéo; player `<video>` avec poster fallback.
5) **Nettoyage / suppression** : delete action détruit l’ancien asset (video/image) avec type correct; upload interdit public.
6) **Doc / Env** : env `CLOUDINARY_*` requis; assets en lecture signée uniquement; build/seed validés local.

## Livrables attendus
- Prisma mis à jour (`videoPublicId`).
- Server action/route de signature + (optionnel) delete.
- UI upload/remplacement vidéo dans création/édition de position.
- Lecteur vidéo intégré sur fiche position (et éventuellement catalogue).
- Doc env/Render mise à jour.

## Risques / mitigations
- Quota Cloudinary : limite 100MB côté client, message clair, resource_type=video forcé.
- Fuite secret : signature server-only.
- Données orphelines : delete sur remplacement/suppression, prévoir cleanup périodique si besoin.
