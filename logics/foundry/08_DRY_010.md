# 08_DRY_010 — Vidéos Cloudinary pour positions (upload signé + lecteur)
[Aligné v0.8.1 | Confiance: 88% | Avancement: 0% | Portée: S011 P?]

## Objectif
Permettre l’upload de vidéos de positions vers Cloudinary (upload signé côté serveur), stocker l’URL dans la position, et afficher un lecteur vidéo intégré (poster généré). Options de remplacement/suppression sécurisées.

## Portée (in) / (out)
- (in) Upload signé Cloudinary pour positions, stockage `videoUrl`/`videoPublicId`, preview/lecture native `<video>`, remplacement/suppression du média.
- (out) Transcodage avancé, quotas/billing Cloudinary, upload multi-fichiers (audio/steps), gestion hors positions (cours/presets) sauf si demandé ensuite.

## Hypothèses / Pré-requis
- Env à ajouter : `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`, `CLOUDINARY_FOLDER` (ex: poleapp/positions), `MAX_VIDEO_MB` optionnel.
- Provider Cloudinary autorisé pour les images/vidéos (host déjà whitelisted si besoin).
- Champ `videoUrl` déjà présent sur Position; ajouter `videoPublicId` si on veut supprimer/remplacer proprement.

## Plan détaillé
1) **Modèle / Prisma**
   - Ajouter `videoPublicId` (nullable) sur `Position`.
   - `db push` + seed ajusté (optionnel) pour positions démo avec vidéo factice.

2) **Signature upload (server)**
   - Route API ou server action `sign-cloudinary-upload` qui génère `timestamp`, `public_id` (avec folder), `signature` (SHA1 des params + secret).
   - Valider rôle (prof/admin) et éventuellement limite de taille/type (param `resource_type=video`).

3) **UI upload (formulaire position)**
   - Bouton “Uploader une vidéo” qui appelle la signature, puis `fetch` Cloudinary `https://api.cloudinary.com/v1_1/<cloud_name>/video/upload`.
   - Afficher progression / état, stocker `secure_url` + `public_id` dans des inputs hidden (`videoUrl`, `videoPublicId`).
   - Permettre suppression/remplacement (reset des champs + option delete côté Cloudinary).

4) **Lecture / preview**
   - Sur les pages position (liste + détail) : afficher `<video controls>` avec poster Cloudinary (`.../so_0.jpg`), fallback image placeholder.
   - Gérer gating premium existant (ne pas exposer la vidéo si non autorisé).

5) **Nettoyage / suppression**
   - Lorsque la vidéo est remplacée, appeler Cloudinary `destroy` (server action) avec `public_id` précédent (optionnel mais recommandé).

6) **QA / Doc**
   - Tests manuels : upload < limite, upload mauvais type, remplacement, suppression, lecture mobile/desktop.
   - Doc env vars + procédure Render (ajouter secrets, rebuild).

## Livrables attendus
- Prisma mis à jour (`videoPublicId`).
- Server action/route de signature + (optionnel) delete.
- UI upload/remplacement vidéo dans création/édition de position.
- Lecteur vidéo intégré sur fiche position (et éventuellement catalogue).
- Doc env/Render mise à jour.

## Risques / mitigations
- Erreurs quota/poids Cloudinary : exposer message clair, limite côté client (`MAX_VIDEO_MB`), vérifier `resource_type`.
- Fuite de secret : ne jamais signer côté client, API protégée par auth prof/admin.
- Données orphelines : si pas de delete, prévoir cleanup ultérieur (cron ou script).
