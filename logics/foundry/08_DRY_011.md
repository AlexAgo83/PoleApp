# 08_DRY_011 — Header unifié (renard, boutons, sans texte)
[Aligné v0.12.11 | Confiance: 85% | Avancement: 100% | Portée: multi-pages headers]
> Chantier sur le header terminée

## Objectif
Redsign du header de page ; Sur chaque page il y'a un header qui contient le logo du renard, des boutons et du texte.

- Nous avons besoin de supprimer les textes
- De déplacer tout les boutons dans le coin haut droit du panel
- D'avoir un composant partagé pour le header, et si possible d'avoir le moins possible de custom par page pour l'intégrer et le modifier.

## Portée (in) / (out)
- (in) Tous les headers de pages avec le renard (catalogues, positions, presets, admin/teacher/student dashboards) : suppression du texte descriptif, alignement des CTA en coin haut-droit, rendu homogène (padding, overlay, ratio du renard).
- (in) Création d’un composant partagé (ex. `FoxPageHeader`) paramétrable via props (titre, rôle/eyebrow, liste de boutons, lien maison), utilisable sur les pages concernées avec un minimum d’overrides.
- (out) Refonte du contenu des pages ou des CTA eux-mêmes (seulement leur placement/présence). Pas de changement de logique métier, ni des breadcrumbs/nav secondaires, ni du responsive global hors header.

## Hypothèses / Pré-requis
- Toutes les pages concernées importent déjà le renard/logo et ont un bloc header en panel (background gradient + image). On peut factoriser sans toucher aux données.
- Les CTA existants restent valides (mêmes href/labels), seul leur placement change (stack en haut à droite).
- Le composant partagé accepte les variations de rôle (admin/teacher/student) mais reste neutre visuellement (pas de textes auto).
- Le renard utilisé est celui de `FoxVignette` (`CircularRedFox` / `PlainRedFox`) : pas d’autre variante à créer.
- Design commun proposé : panel `p-6 md:p-8` avec overlay `linear-gradient(135deg, rgba(10,15,30,0.85), rgba(15,25,45,0.7))`, image en fond si dispo sinon gradient seul. Renard centré gauche (ou centré absolu si déjà), boutons groupés en haut/droite (`flex-wrap gap-2 justify-end`). Pas de texte descriptif sous le titre. Eyebrow facultatif (rôle/page).
- CTA : labels/href existants conservés ; ordre par importance (Retour, actions secondaires, actions primaires). Responsive : wrap en 2 lignes si besoin.

## À faire / Plan
1) Créer un composant partagé `FoxPageHeader` (ou similaire) : props `eyebrow`, `title`, `buttons[]` (label, href, variant), option `backgroundImage`/`foxHref`, slot enfant optionnel pour contenu personnalisé (rare).
2) Remplacer les headers existants (pages avec renard) par ce composant : suppression des paragraphes descriptifs, boutons regroupés en haut à droite.
3) Ajuster les styles communs (padding, overlay, ratio renard, alignement mobile/desktop).
4) Vérifier responsive (mobile : boutons wrap en haut à droite, renard reste centré/visible).

## Livrables attendus
- Nouveau composant header partagé + styles.
- Pages refactorées utilisant le composant, sans textes descriptifs et avec CTA en coin haut-droit.
- Cohérence visuelle (espacements, overlays) validée sur admin/teacher/student principaux, positions/presets.

## Risques / mitigations
- Variations locales non prévues (CTA conditionnels) : prévoir un slot/custom actions.
- Régressions responsive : tester mobile/tablette, vérifier que le renard ne masque pas les boutons.
- Overlay/fond selon page : accepter un `backgroundImage` ou fallback pour éviter les gaps.
- A11y : s’assurer du contraste (textes sur overlay), aria-label sur CTA icônes, ordre tab naturel (titre avant boutons si besoin).
